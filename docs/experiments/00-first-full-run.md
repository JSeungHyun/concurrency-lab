## 눈에 띄는 점 (검증 전 메모)

- **naive 는 100장 쿠폰을 2000장 발급했다.** 카운터 컬럼은 정확히 100 으로 끝나서, 카운터만 보면 정상처럼 보인다. 행 수를 세야 문제가 보인다는 점이 1편의 좋은 소재다.
- naive 가 가장 느린 건 역설적으로 "매진 판정이 늦게 나서" 2000건이 모두 INSERT 까지 갔기 때문으로 보인다. 다른 전략은 100건 이후 바로 거절한다.
- optimistic 은 p50 은 가장 낮은 편인데 p95/p99 가 크게 튄다. 재시도 1858회가 꼬리 지연을 만든다.
- redisson-lock 은 이번 조건에서 synchronized·pessimistic 보다 느리다. 락 획득/해제마다 Redis 왕복이 붙고 pub/sub 대기가 있다.
- redis-lua 는 p50 6.8ms 로 압도적이지만 p99 는 891ms. 앞단 100건의 DB 기록이나 초기 커넥션 비용으로 추정되며 확인이 필요하다.
- synchronized 가 통과한 건 앱이 1대이기 때문이다. scale-out 실험 전까지는 "통과" 로 쓰면 안 된다.
